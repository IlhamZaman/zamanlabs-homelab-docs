# Contributing to the Documentation

This is a personal homelab documentation repository, but the same workflow should be used for every update.

1. Put the document in the folder for the system it describes.
2. Use a descriptive filename, not a new STEP number.
3. State the goal and affected systems near the top.
4. Separate implementation, verification, troubleshooting, and rollback.
5. Replace secrets with clear placeholders.
6. Check links and commands before committing.
7. Update the nearest folder README and the root index when adding a major component.

Use Markdown headings, fenced code blocks, tables only where they improve scanning, and Mermaid diagrams for architecture that is easier to understand visually.
